# parametric_curves_xr — **r**(t) = (A·sin(a t+α), B·sin(b t+β), C·sin(c t+γ)) ในห้องจริง (WebXR)

สื่อการสอน VR ไฟล์เดียวจบ ผู้เรียนเห็น **แบบจำลองของเส้นที่เกิดจากสมการที่ตัวเองเลือก ลอยอยู่ตรงหน้าในระดับสายตา พอดีกรอบมอง** — ไม่ต้องแหงน ไม่ต้องเข้าไปอยู่ในนั้น แล้วเดินวนรอบมันได้
สาม oscillillator บนสามแกน ใช้ **ตัวแปรเดียวกันคือ t** แต่คนละความถี่ — สิ่งที่ผู้เรียนเห็นคือ
เส้นที่ค่อย ๆ ถูกวาดขึ้นจากความว่าง แล้วจุดที่วิ่งไล่ตามเส้นคอยวาดทับให้เข้มกลับ พร้อมหน้าปัดสามเรือนที่โชว์ว่าแต่ละแกนเดินไปกี่รอบแล้ว ณ วินาทีเดียวกัน

**invariant ของสื่อไฟล์นี้: ไม่มีคำอธิบาย ไม่มีประโยค ไม่มีป้ายคำ ไม่มี tooltip**

เรขาคณิต · สี · การ์ดที่เป็น `1 2 3 4` `∥ ◯ ⬭ ∿ ◎ ≣ ∞ 1:2:3 … ⧉ ⟲ ‖ ▶ ⏩ Δφ ◐` เท่านั้น

### 1.1 แบบจำลองลอยอยู่ตรงหน้า: เวทีถูกห่อให้พอดีกรอบมอง

เส้นจริงของทุกพรีเซตกินพื้นที่กล่อง 14×14×8 m ถ้าวาดขนาดเต็มผู้เรียนต้องยืนใต้เส้นและเงยคอมอง
สื่อจึงวาด **แบบจำลองย่อส่วน ×s** ที่ลอยอยู่ข้างหน้า โดย `fitStage()` แก้หา s และตำแหน่งจาก
**เส้นที่เลือกจริง + กรอบมองจริงของกล้อง** (อ่าน `projectionMatrix` ของกล้อง XR ขณะ presenting
หรือของกล้องจอแบนเมื่อไม่ presenting — `cameraHalfAngles()`):

| ค่าคงที่ `STAGE` | ความหมาย |
|---|---|
| `nearM = 2.58` | จุดของเส้นที่ **ใกล้ตาที่สุด** ต้องอยู่ห่าง=this (เวทีทั้งเวทีมาอยู่ใกล้ตามผู้สอนขอ = 0.6 เท่าของระยะเดิม) |
| `fitH = 0.78` | เส้นกินได้ไม่เกิน 78% ของครึ่งกรอบมอง (ทั้งแนวตั้งและแนวนอน) = พอดีกรอบแต่ไม่ล้น |
| `upDeg = 9` | ไม่มีจุดใดของเส้นสูงเกิน 9° เหนือแนวสายตา = **ไม่ต้องแหงน** (จุดสูงสุดที่วัดได้ ≤ 9.1°) |
| `clearM = 0` | ไม่ให้เส้นลอดต่ำกว่าพื้น (0 = แตะระนาบ z=0 ได้ ซึ่งเส้นข้ามอยู่จริงในคณิตศาสตร์) |
| `maxS = 0.60` | เพดานของ s |

ผลคือ `ST = {s, D, L}` — s คือมาตราส่วน, D คือระยะถึงระนาบกึ่งกลางของเส้น, L คือความสูงของ
ระนาบ z=0 ของแบบจำลอง; ทุกจุดที่สื่อวาดผ่าน `to3()` ช่องเดียว (`index.html` §2) จึงย้ายตามเวที
ทั้งฉากพร้อมกัน เมื่อเปลี่ยนเส้นหรือเปลี่ยนขนาดจอ/เริ่ม session XR สื่อ **แก้ห่อใหม่**
(`ensureStage()` ตรวจ cache key ที่มีครึ่งกรอบมองอยู่ด้วย แล้วสร้างท่อใหม่) s ที่ได้อยุ่ระหว่าง
0.24–0.32 (ค่าเฉลี่ย 0.261 = 120% ของรุ่นก่อนตามที่ผู้สอนขอ) = แบบจำลองกว้าง 3.4–4.5 m สูง 1.9–2.6 m
แล้วแต่ว่าเส้นนั้นกินกรอบการมองเพียงใด (เส้นจริงกินกล่อง 14×14×8 m) จุดใกล้ที่สุดห่างตา 2.58 m

**ราคาที่ต้องจ่าย (พูดตรง ๆ):** ห้องเดินจริงคือ ±8 m แต่แบบจำลองกว้างได้ถึง 4.5 m
จึง **ร่างกายไม่ได้รู้สึกความยาวจริงของเส้น** (เส้น 605.8 m กลายเป็นวงกว้าง 3.6 m ในห้อง 16 m)
ความยาวจริง ตัวเลขจริง และอัตราส่วนจริงอยู่ที่แผงตัวเลขและใน README นี้
และแกน x, y, z ที่วาดบนพื้นพร้อมตัวเลข `±2 ±4`, `z=±2`, `z=±4` คือ **ค่าพิกัดจริงของเส้น**
ไม่ใช่ระยะเมตรในห้อง — อ่านคู่กับแผงตัวเลขเสมอ
ราคาอีกข้อ: เมื่อวางทั้งเส้นไว้ข้างหน้าทั้งหมด **ผู้เรียนเห็นเส้นจากทิศเดียวเป็นหลัก**
การเห็นว่าเส้นตัดตัวเองจริงหรือเข้าใกล้จุดเริ่มต้นจริงแค่ไหน ต้องอาศัยการเดินวนรอบ (ซึ่งถูกกันไว้ด้วย keep-out)

### 1.2 การวาดเส้น: รอบแรกจากที่ว่างเปล่า → จางทั้งเส้น → จุดที่วิ่งวาดทับให้เข้มกลับ

`revealFraction()` ใช้ `drawRange` ของท่อและเงาเขียนเส้นไปเรื่อย ๆ ตาม t (รอบแรก = เห็นมันถูกสร้างจากความว่าง)
เมื่อครบหนึ่งคาบ (`S.kPeriods ≥ 1`) ทั้งเส้นมีอยู่ครบและเข้าโหมด "วาดซ้ำ": ทุกส่วนของเส้น
จางลงช้า ๆ ตามเวลาที่ผ่านจุดนั้นไป และจุดที่วิ่งตามเส้นทิ้ง **แถบสว่างสั้น** ไว้ข้างหลังมัน
ส่วนที่ถูกวาดทับแล้วกลับมาเข้มเท่าเดิม ส่วนที่ยังไม่ถูกแตะก็ยังจาง

ความสว่างของแต่ละจุด = `1 − (1−PAINT.dim)·clamp(age/PAINT.fadeLap, 0, 1)` โดย
`age = min(เศษของคาบตั้งแต่จุดที่วิ่งผ่านจุดนี้, จำนวนคาบที่ผ่านพ้นรอบแรกมาแล้ว)` และแถบสว่าง
`PAINT.glow` ที่ด้านหลังจุดที่วิ่งในระยะ `PAINT.glowW` ของหนึ่งคาบ
สีตั้งต้นของทุกส่วนของเส้นถูกเก็บไว้ที่ `tubeBase`/`shBase` แล้วคูณด้วยตัวประกอบนี้ทุกเฟรม
(ทั้งท่อและเงาบนพื้น) — ค่าคงที่ `PAINT = { dim 0.14, fadeLap 0.55, glow 0.34, glowW 0.02, shDim 0.34 }`

* รอบแรก `age = 0` ทุกจุด → เส้นสว่างเต็มที่ทั้งที่ยาวขึ้นเรื่อย ๆ (ผู้เรียนเห็นการสร้างเส้น)
* ต่อคาบต่อเนื่องไม่มีขั้นกระโดดของความสว่างที่รอยต่อรอบ (สูตรใช้เศษของคาบ)
* **ใช้กับเส้นปิดเท่านั้น** เส้น `1:1:√2` ไม่ปิด → การเขียนจบที่ `t = span` แล้วหยุด ไม่มีจาง ไม่มีวาดทับ
  (`paintState().done = 0`)
* ในโหมด `⧉` เส้นของอีกคู่ที่นำมาเทียบวาดเต็มความยาวตั้งแต่ต้น ส่วนท่อหลักค่อย ๆ ถูกเขียน (ข้อจำกัดที่มีอยู่จริง)

ซึ่งขึ้นกับความถี่ตัวอย่าง — การทดสอบจึง assert เป็นเกณฑ์ (แบน = deviation < 1e-9,
อยู่บนทรงกระบอก = < 1e-13) ไม่ใช่ค่าตายตัว

ข้อที่สื่อไม่ได้พูดแต่ตัวเลขแสดงอยู่: `∥ ◯ ⬭ ∿` planarityDeviation < 1e-9 (แบนจริง), `◎ ∞ 5:5:7 12:12:17 1:1:√2`
cylinderDeviation < 1e-13 (ถูกกักบนทรงกระบอก x²+y²=49), `≣` อยู่บนทรงกระบอกเชิงรี
และ √2 ที่ 12 รอบ กับ 12:12:17 ต่างกันแค่ **0.06%** ของความยาว

## 3. โหมดเทียบสองเส้น `⧉` — สองเส้นในหน้าจอเดียวกัน

จ้องการ์ด `⧉` (หรือกด `X` บนจอแบน) = **เส้นล่าสุดที่เคยเปิดดู** ถูกวาดทับลงไปเป็นท่อจางบาง + เงาจาง
พร้อมแถบตัวเลขท้ายแผง: `T₂`, `L₂`, `max|π₂r₁ − π₂r₂|` (ระยะ Hausdorff ของ **เงา** บนพื้น) และ
`max|r₁ − r₂|` (ระยะ Hausdorff ของ **ตัวเส้น** ใน 3 มิติ) — คำนวณด้วย `math_core.shadowGap` / `curveGap` (n=700)

| เส้นที่กำลังดู | เส้นเทียบ | เงาต่าง (m) | ตัวเส้นต่าง (m) | บทเรียนที่เกิดตรงหน้า |
|---|---|---|---|---|
| `≣` | `1:2:3` | **0.0000** | **6.3652** | สมการต่างโดยสิ้นเชิง แต่ **เงาบนพื้นเหมือนกันทุกจุด** — ภาพ 2D แยกสองเส้นนี้ไม่ได้ |
| `◎` | `∞` | **0.0000** | **5.9374** | เงาเป็นวงกลมเดียวกัน เกลียวคนละชั้น |
| `⬭` | `◯` | **0.0000** | **2.6962** | วงรีสองอันใน **ระนาบต่างกัน** แต่เงาบนพื้นเหมือนกัน |
| `1:2:3` | `2:4:6` | **0.0000** | **0.0000** | เส้นเดียวกันจริง ต่างกันแค่ความเร็วและคาบ |
| `1:1:√2` | `12:12:17` | **0.0000** | **0.7356** | ตัวประมาณตรรกยะให้เส้นที่ "เกือบ" เหมือน แต่ของจริงไม่ปิด |
| `3:4:5` | `2:3:5` | **1.5208** | **5.0531** | บางคู่เปลี่ยนอัตราส่วนแล้ว **ทั้งเงาก็เปลี่ยน** |

## 4. การควบคุม

### ในแว่น (gaze-dwell เท่านั้น — ไม่มีเมาส์ ไม่มีจอย)
* **จ้องการ์ดค้าง 1.2 s** (cooldown 0.9 s, กรวย 6°) — การ์ด billboarding ตาม**ลำตัว**
  ทั้งเมนูอยู่ต่ำกว่าสายตาทั้งหมด แถวบนสุดต้องก้ม 22° (ต่ำกว่ารุ่นก่อน 30°):
  * แถว 1 (`pitch −22°`, ระยะ 3.00 m) `1` `2` `3` `4` เลือกกลุ่ม (มีภาพย่อของเส้นแรกในกลุ่ม + จำนวนเส้น)
  * แถว 2 (`pitch −38°`, ระยะ 1.95 m) `∥ ◯ ⬭ …` เลือกเส้น (badge = สัญคณิต, sub = `T=…` หรือ `T=∄`)
  * แถว 3 (`pitch −52°`, ระยะ 1.57 m) `⟲` ล้างเวลา · `‖/▶` เล่น/หยุด · `⏩` ความเร็ว ·
    `Δφ` เลื่อนเฟสแกน z ทีละ 22.5° (−8…+8 คลิก) · `◐` เปิด/ปิดเงา · `⧉` เทียบสองเส้น
  * ระยะของแต่ละแถวคำนวณจาก `rowDist()` ให้ขอบล่างการ์ดยังอยู่เหนือพื้น 0.30 m และการ์ดถูกย่อ
    ตามระยะเพื่อว่า **มุมที่การ์ดกินในสายตาเท่าเดิมทุกแถว**
  * ตรงกลางด้านหน้า ±22° เป็นของเส้นเท่านั้น (ไม่มีการ์ดบัง)
* **ก้มมอง = เดิน** ตามทิศที่มอง: ก้ม 26° เริ่มเดิน, 46° = เต็มความเร็ว 2.3 m/s (accel ≤ 2.5 m/s²)
  เกณฑ์เดียวกับ `../walking_xr/`; ขอบสนาม ±8 m เว้น 1.0 m
  **และห้ามเดินเข้าไปในบริเวณของแบบจำลอง** (keep-out รัศมี `1.0 + s·√(7²+7²)` m รอบจุดศูนย์กลางเวที = 3.4–4.2 m ตามเส้นที่เลือก (กรณีทดสอบที่วัดจริงได้ 3.56 m)
  → จากจุดเริ่มเดินไปทางเส้นได้ประมาณ 0.9 m แล้วถูกกันไว้: ด้านข้างและข้างหลังเดินอิสระ)
  ขณะกำลังจ้องการ์ดหรือมองแผงตัวเลขอยู่ การเดินถูกพักไว้ = อ่านเมนู/อ่านแผงได้โดยไม่เลื่อนตำแหน่ง
* คอนโซลตัวเลข = แผงแบนตรงหน้า `pitch −28°` ระยะ 2.05 m ขนาด 0.98×0.44 m (60% ของรุ่นก่อน)
  การ์ดอยู่กับลำตัว
* ไม่มีจอยสติก/คีย์บอร์ดในแว่น — การเลือกทั้งหมดคือ gaze

`math_check.mjs` ตรวจคณิต **อิสระ** จากสื่อ: `4√114`, `4√65·E(16/65)` (E โดย quadrature),

การลู่เข้าของ Simpson (n=250…8000 ต่างกัน < 3e-9), และ `nearestRatio(√2, 40) = 41/29`

`shot.py` ยืนยันว่า **สื่อเอง** (ตัวที่รันใน browser) คำนวณตรงกับค่าเหล่านั้น — เทียบ `T`, `L`,
`|sArc − sExact|`, planarity/cylinder, เวลาที่ r(t)=r(0), อัตราส่วนช่องว่างของขีดเวลา,
`cycles == a·t/2π`, และระยะเทียบของโหมด `⧉`

สามข้อที่เพิ่มมาพร้อมการจัดวางและการวาดแบบปัจจุบัน:
* **`frame` (15 เส้น):** `frameCheck()` ในสื่อวัดจุดของเส้นจริง 900 จุด ผ่าน `to3()` และ
  ครึ่งกรอบมองของกล้องที่ใช้งานอยู่ ณ เวลานั้น → ต้องไม่แหงน (จุดสูงสุดเหนือสายตา ≤ 11.5°),
  กว้าง ≤ 85% ของครึ่งกรอบ, สูง ≤ 100% ของกรอบ, จุดต่ำสุดไม่เลย 95% ของกรอบแนวตั้ง,
  และจุดใกล้สุดไม่ใกล้ตากว่า 2.4 m · ผลที่วัดได้จริง: สูงสุด ≤ +9.1°, กว้าง ≤ 78%, สูง ≤ 62%,
  ระยะ 2.58…7.1 m
* **`paint`:** รอบแรกต้องเห็นเส้นถูกวาดจากที่ว่าง (`reveal < 1` และส่วนที่วาดแล้วสว่างเต็มที่)
  พอครบหนึ่งคาบต้อง `reveal = 1` และความสว่างเรียงเป็นแถบ: เพิ่งวาดทับ 0.95 › ผ่านมา 0.30 คาบ 0.53
* **`walk` 2 เคส:** ก้มแล้วผู้ใช้เคลื่อนที่จริง อยู่ภายในสนาม ±8 m และ **ไม่เข้าไปในบริเวณของแบบจำลอง**
  (วัดระยะจากศูนย์กลางเวทีเทียบ `keepOutR` = 3.56 m)
  ข้อจำกัดที่วัดได้: เดินจากจุดเริ่มไปทางเส้นได้ ~0.9 m แล้วถูกกันไว้ (ด้านข้าง/ข้างหลังเดินอิสระ)
  ข้อทดสอบวัดแนวศูนย์กลางของเส้น ความหนาของท่อเพิ่มอีก ~1° ที่จุดใกล้ที่สุด

## 8. สถานะงาน

* ผ่าน `math_check` 203/203 และ `shot.py` 28/28 (รวมข้อทดสอบกรอบมองและการวาด)
* **ยังไม่ได้ทดสอบกับผู้ใช้จริงใน headset** — ยังไม่มีข้อมูลว่า ผู้เรียนหากาด `⧉` เจอหรือไม่,
  ใช้เวลากี่วินาทีต่อการเลือกหนึ่งครั้ง, หรือแบบจำลองที่ระยะ 2.6 m ทำให้เวียนศีรษะหรือไม่
* **ยังไม่ทราบว่าตัวอักษรบนแผงตัวเลขอ่านได้ใน headset จริงหรือไม่** แผงยังวาดบน canvas 1440×640 เดิม
  แต่แผงจริงเหลือ 0.98×0.44 m → pixel บนแผง = 0.68 mm ตัวอักษรขนาด 24 px จึงสูง ≈ 16 mm
  ที่ระยะ 2.05 m = **≈ 0.46° ของมุมมอง** (เดิม 1.14 mm/px ให้ ≈ 0.76°) — บนจอแบนยังมี HUD
  ที่แสดงตัวเลขชุดเดียวกันด้วยอักษร 12.5 px แต่ในแว่นไม่มี HUD นั้น ถ้าอ่านไม่ออกต้อง
  ลดจำนวนตัวเลขบนแผงแล้วขยายตัวอักษร (ยังไม่ได้ทำ)
* แบบจำลองเป็น **ย่อส่วน** (s ≈ 0.24–0.32 = กว้าง 3.4–4.5 m) และถูกกันไม่ให้เดินเข้าไปในบริเวณของมัน
  ผู้เรียนจึงไม่ได้รู้สึกความยาวจริงของเส้นด้วยร่างกาย — ตัวเลขความยาวจริงอยู่ที่แผงและเอกสารนี้
* ใบงานคู่สื่อยังไม่เขียน — สิ่งที่ใบงานต้องทำคือถามสิ่งที่ภาพตอบไม่ได้
  ("ทำไม `∥` กับ `◯` จึงเป็นระนาบเสมอ", "ทำไม `min Δ` เล็กลงทุกครั้งที่เขียนเพิ่มรอบแต่ไม่มีวันเป็น 0")
