# PCA_XR — กระจุกข้อมูล "ทรงรี" ที่สุ่มใหม่ทุกครั้ง + แกนหลักที่คำนวณจากข้อมูลจริง (WebXR)

สื่อการสอน VR ไฟล์เดียวจบ ผู้เรียนเห็น **กระจุกจุด 300–2400 จุดที่เกิดจากการสุ่มจริง ลอยอยู่ตรงหน้า
ขนาดเท่าตัวคน ที่ระยะ 2 m** แล้วเห็น **แกนสามเส้นที่สื่อคำนวณเองจากข้อมูลชุดนั้น** (eigenvector ของ
covariance) พร้อมขีด σ, 2σ บนแกนเหล่านั้น

หัวใจของสื่อคือคำถาม **"ข้อมูลหน้าตาเป็นอย่างไร เมื่อถูกฉายเหลือแค่ 2 มิติ / 1 มิติ"** —
ผู้เรียนก้มมองการ์ด `ℝ³` `ℝ²` `ℝ¹` แล้วเห็นกลุ่มจุดเดิม **ยุบลงเป็นแผ่น / ยุบลงเป็นเส้น**
พร้อมเส้นสั้น ๆ จากจุดเดิมถึงจุดที่ถูกฉาย ซึ่งคือ `‖x − π(x)‖` ที่หายไปจริง ๆ ทุกจุด

**ทุกรอบที่เข้าสื่อ ข้อมูลเป็นชุดใหม่** (`seed → seed+1`) และแกนที่วาดเปลี่ยนตามข้อมูลจริง
ไม่มีเลขชุดใดถูก hardcode ไว้ใน `index.html`

**invariant ของสื่อไฟล์นี้: ไม่มีคำอธิบาย ไม่มีประโยค ไม่มีป้ายคำ ไม่มี tooltip ในฉาก 3D**
สิ่งที่มีได้คือ ตัวเลข · สัญคณิต (`λ σ v Ĉ tr det χ(t) Σλ Πλ π(x) x̄ μ ‖x−πx‖ σ 2σ ℝ³ ℝ² ℝ¹ ⟳ ⟲ ⊞ ◍ ◐ √ ⋀`) ·
เรขาคณิต · สี · การ์ดสัญลักษณ์เท่านั้น — ภาษาทั้งหมดอยู่ใน README นี้ (และ HUD ภาษาไทย
ที่แสดงเฉพาะบนจอแบน นอกฉาก 3D)

ทุกตัวเลขที่เห็นบนจอมาจาก `tools/math_core.mjs` — โมดูลเดียวกับที่ `tools/math_check.mjs` ใช้ตรวจ

## 1. สิ่งที่ภาพสื่อ (ไวยากรณ์ภาพของสื่อ)

| สิ่งที่ผู้เรียนเห็น | ความหมาย |
|---|---|
| กระจุกจุดสีอ่อนเป็นรูป **ทรงรี** ลอยตรงหน้า | ข้อมูลจริง `x ∈ ℝ³` ที่สื่อสร้างเอง: `x = x̄ + R·diag(σ)·z` เมื่อ `z ~ N(0,I)` และ `R` เป็นการหมุนสุ่ม (unit quaternion) — ไม่มีหน้าตาข้อมูลแบบใดถูกวางไว้ล่วงหน้า |
| **โครงเส้นทรงรี** สีฟ้าครอบกระจุก (การ์ด `◍ 2σ`) | ellipsoid ครึ่งแกน `2σᵢ = 2√λᵢ` — เส้นที่ "ควรจะเป็น" ถ้าข้อมูลเป็นการแจกแจงเกาส์เซียนสมบูรณ์ จึงเห็นทันทีว่าข้อมูลจริงเลยเส้นออกไปแค่ไหน (λ จริงของข้อมูลชุดนี้ ไม่ใช่ค่าที่ตั้งไว้) |
| ลูกศรหนา **สีส้ม / ฟ้า / ชมพู** ผ่านกลางกระจุก | `v₁ v₂ v₃` = eigenvector ของ `Ĉ = 1/(n−1) Σ (x−x̄)(x−x̄)ᵀ` ที่สื่อหาเองด้วย **Jacobi rotation** (บนแผงมี `sweeps = 4` และ `max‖Ĉv−λv‖`) ความยาวลูกศร = ระยะที่ข้อมูลไปไกลที่สุดจริงในทิศนั้น `max|q·vᵢ|` ไม่ใช่ค่าสมมุติ |
| ขีด + ป้าย `σ₁ 2σ₁` บนลูกศร | มาตราส่วนของการกระจายตามแกนนั้น = `√λᵢ` (บนแกนที่สั้นมาก ป้ายถูกซ่อน ดู §8) |
| **จุดสว่าง** = ภาพฉาย `π(x) = Σⱼ (q·vⱼ)vⱼ` (j = ทิศที่เหลืออยู่) | **"หน้าตาข้อมูลในมิติที่ลดลง"** ซึ่งเป็นคำตอบของคำถามหลัก — ใน `ℝ¹` มันคือเส้นบาง ๆ ตาม `v₁`, ใน `ℝ²` คือแผ่นจุดบนระนาบ `v₁∧v₂` |
| **จุดจาง** + **เส้นบางจากจุดจางไปยังจุดสว่าง** | ข้อมูลเดิมก่อนฉาย และ residual `x − π(x)` — สิ่งที่หายไปจากการลดมิติ วาดเป็นเส้นจริงทุกจุด (การ์ด `◐ ‖x−πx‖`) |
| **แผ่นบางสีฟ้าพร้อมขอบ** เมื่อเหลือ 2 มิติ | ขอบเขตของมิติที่เก็บไว้ = `span{v₁, v₂}` กว้างตามครึ่งช่วงจริงของข้อมูลที่ฉายแล้ว |
| **เส้นประสีเทา + ป้ายชื่อ** ของแกนที่ไม่ได้ใช้ | สิ่งที่ตัดสินใจทิ้ง — เห็นว่า `v₃` ยังอยู่ในฉาก แต่ไม่มีจุดใดของภาพฉายอยู่นอกมัน |
| **จุดทรงแปดหน้าสีชมพู + ป้าย `x̄`** | จุดกลาง ที่ถูกย้ายไปเป็น origin — ทุกแกนและทุกการฉายวัดจากจุดนี้ (ไม่ใช่จุดที่ยืนอยู่) |
| การ์ด `μ ‖μ‖=0.50` → กลุ่มจุดจางอีกชุด + เส้นประจาก `x̄` | **centering**: แสดงตำแหน่งข้อมูลก่อน centering และเวกเตอร์ `μ` เพื่อให้เห็นว่า PCA เริ่มด้วยการย้าย `x̄ → 0` (ตัวเลขจริงของ `‖μ‖`) |
| เส้นบาง `x y z` สีแดง/เขียว/น้ำเงิน (การ์ด `⊞ x y z`) | แกนดิบของข้อมูลที่ข้อมูลถูกสุ่มมา — เทียบให้เห็นว่า `v₁` **ไม่ได้อิงแกนของระบบพิกัด** และแกนดิบเก็บ variance ได้น้อยกว่า `v₁` เสมอ |
| **แผงตัวเลข** ลอยใต้กระจุก (ก้ม 28°) | ทุกค่าที่กล่าวถึงข้างบนเป็นตัวเลขจริงพร้อมแถบความยาว: `λ σ √λ %`, องค์ประกอบ `vᵢ`, `vᵢᵀĈvᵢ`, `tr Ĉ`, `det Ĉ`, `χ(t)`, ตัวเลข 9 ช่องของ `Ĉ`, เอกลักษณ์ 3 บรรทัดด้านล่าง |
| **ตารางแถบขวาบนแผง** `vᵀĈv / tr Ĉ` | ทำไม `v₁` ชนะ: แถบของ `v₁ v₂ v₃ x y z u` และระนาบ `v₁∧v₂`, `v₂∧v₃` — เรียงตามค่าจริงที่คำนวณจาก `Ĉ` |
| การ์ด 3 แถวที่ก้มมอง (ภาพย่อ + `100.0% 98.9% 79.8%`) | เมนูที่ไม่ใช้คำ: ภาพย่อของโหมดบนหน้าการ์ดบอกว่าจะเกิดอะไรขึ้น, `%` บอกว่าจะเก็บ variance ได้เท่าใด |

### 1.1 กระจุกขนาดราวตัวคน ลอยข้างหน้า: เวทีถูกห่ออย่างไร

ข้อมูลจริงกินพื้นที่ต่างกันทุก seed (บางชุดยาว 6 หน่วย บางชุดแคบ 1 หน่วย) สื่อกำหนด
**กรอบของร่างกาย** ไว้ก่อน แล้วแก้ห่อข้อมูลให้พอดีกรอบนั้นด้วย `stagePlan()` ใน `math_core`
ใน `index.html` ไม่มีตัวเลขเรขาคณิตของฉากเลย

**ขั้นที่ 1 — กรอบพื้นฐาน `STAGE_BASE`** (คือฉากที่ได้เมื่อตัวคูณ `k = 1`):

| ค่าคงที่ของแบบแผน | ความหมาย |
|---|---|
| `longMax = 1.50` | แกน principal ที่ยาวที่สุดที่วาดได้ (วัดตามทิศของข้อมูล ไม่ใช่ตามแกนห้อง) |
| `vertMax = 1.10` | ขนาดในทิศขึ้นของห้อง (world Y) ที่วาดได้ |
| `depthMax = 1.40` | ขนาดในทิศหน้า–หลังของห้อง (world Z) ที่วาดได้ |
| `height = 1.55` | ความสูงศูนย์กลางของกระจุก (ผู้เรียนยืน `EYE = 1.60`) → ฐานล่างกล่องอยู่ที่ 1.00 m |
| `NEAR_TARGET = 1.40` | ระยะด้านข้างถึงหน้าใกล้ของกล่อง: ไม่มีความจุดใดเข้ามาใกล้ตากว่านี้ |
| `CLUSTER_MAX = 2` | เพดานของตัวคูณขยายกระจุก (`?cluster=`) |

`scale = min( longMax/(2·half₀), vertMax/(2·h_z), depthMax/(2·h_y) )` เมื่อ `half₀ = max|q·v₁|`
และ `h_z, h_y` คือครึ่งช่วงจริงของ **ข้อมูลที่หมุนแล้ว** ในทิศขึ้นและทิศลึกของห้อง —
scale จึงผูกกับ **ทิศที่ข้อมูลวางตัวจริง** ไม่ใช่กับขนาดอย่างเดียว (`stage.binding` บอกว่าข้อไหนกำลังผูก)

**ขั้นที่ 2 — ตัวคูณขยายกระจุก `k`** (`?cluster=1…2`, ค่า default = เพดาน 2):
`stageFor(k)` คูณทั้งสามเดือนของกล่องพร้อมกัน ⇒ `scale(k) = k·scale(1)` เป๊ะ และกล่องที่วาด ×k ทุกมิติ
ภาพที่ได้จึงเป็น **สำเนาคล้าย (similarity)** ของข้อมูลเดิม รูปร่างและทิศของข้อมูลไม่เพี้ยนไปกับการขยาย
วัดจริง (seed 20261104): `scale 0.11903 → 0.23806 m/หน่วย` · กล่อง `0.80×0.79×1.27 → 1.59×1.57×2.53 m`

**ขั้นที่ 3 — ระยะยืนคำนวณจากสิ่งที่วาดจริง ไม่ใช่จากเพดานของกล่อง:**

    dist = max( NEAR_TARGET + ครึ่งความลึกที่วาดจริง , longMax/2 )

* ข้อแรกคือ **invariant ที่หนึ่ง**: จุดทุกจุดของกระจุกอยู่ไกลตากว่า 1.40 m เสมอ (หน้าใกล้ของกล่องอยู่ที่ 1.40 m พอดี
  ทุกค่า k) เพราะใช้ *ความลึกจริงที่วาด* ไม่ใช่ `depthMax` — ข้อมูลที่แบนและตื้นจึงไม่ต้องถอยหลังเกินจำเป็น
  (วัดได้ `dist = 1.63–2.10 m` ที่ k=1 กับข้อมูลรูปร่างต่างกัน)
* ข้อที่สองกันข้อมูลที่ตั้งกว้างออกข้าง: ครึ่งความกว้าง ≤ ระยะยืน ⇒ มุมซ้าย–ขวาไม่เกิน 45°
* ผลคือระยะยืน **ไม่** ×k ตามกระจุก: 2.03 m → 2.67 m (= ×1.31 เมื่อ k=2) — กระจุกโตเร็วกว่าการถอยหลัง
  ผู้เรียนเห็นรายละเอียดของข้อมูลมากขึ้นโดยไม่ต้องยืนไกลขึ้นเป็นสองเท่า

**ขั้นที่ 4 — กระจุกโตขึ้นข้างบนเท่านั้น:** `height(k) = height(1) + (vertMax(k) − vertMax(1))/2`
ทำให้ **ฐานล่างของกล่องกระจุกอยู่ที่ 1.00 m ทุกค่า k** (invariant ที่สอง) — การ์ดเมนูสามแถว
(ขอบบนสูงสุดที่วัดจาก scene audit = 0.67 m) และแผงตัวเลข (0.86 m) อยู่ต่ำกว่านั้น จึงไม่มีอะไรบังกัน
จุดที่ต่ำที่สุดของกระจุกที่วาดจริง: 1.16 m (k=1) → 1.31 m (k=2)

ทุกจุดของโลกผ่าน `worldOf(p) = (pₓ, p_z, −p_y)` ช่องเดียว (math x → ขวา, math y → ลึก, math z → ขึ้น; det = +1)

**ตัวเลขที่วัดได้จากหน้าจริง** (seed 20261104, n = 900, default k = 2, โหมด ℝ³):
`scale = 0.23806 m/unit` · แกน `v₁` ที่วาด 3.000 m · กล่องที่จุดกินพื้นที่จริง `1.59 × 1.57 × 2.53 m`
(ขวา × ขึ้น × ลึก) · ศูนย์กลางกระจุกอยู่ที่ `(0, 2.10, −2.67) m` · จุดใกล้ตาที่สุด **1.62 m** ไกลที่สุด 3.99 m ·
มุมซ้าย–ขวาสูงสุด 29.6° · มุมเงย −8.0° … +20.2° · ที่ `?cluster=1` ทุกตัวเลขเป็นครึ่งหนึ่ง (ใกล้ตา 1.47 m)

**ราคาที่ต้องจ่าย (พูดตรง ๆ):** `variance` จริง (λ₁ ≈ 3.32) กับ "เมตรในห้อง" คนละหน่วยกัน
สื่อจึงเป็น **ย่อส่วน** — ผู้เรียนเห็น *รูปร่างและทิศ* ของข้อมูล ไม่ได้รู้สึกขนาดของ variance ด้วยร่างกาย
ค่า λ, σ, %, และมาตราส่วนจริงอยู่บนแผงตัวเลขและในเอกสารนี้
ข้อที่สอง: เพราะกระจุกถูกวางไว้ข้างหน้าทั้งหมด ผู้เรียนเห็นมันจากด้านหน้าเป็นหลัก
การเห็นว่าการฉาย "ยุบ" ข้อมูลจริง ๆ ต้องอาศัยการเดินวนรอบ (ดู §4)

    ข้อที่สาม (มาเป็นราคาของการขยายกระจุก): ที่ `k = 2` กระจุกกินมุมมองมากขึ้นจริง — ภาพนิ่งและ
    scene audit วัดได้ว่าจุดบนสุดอยู่สูง 2.6–3.2 m และมุมเงยถึงจุดขอบบน 20° ในกรณีปกติ
    และถึง 35° เมื่อข้อมูลตั้งขึ้นในทิศขึ้นของห้อง · มุมซ้าย–ขวาถึง 30° (กรณีปกติ) ถึง 45° (กรณีกว้าง–แบน) ซึ่งเป็นขอบของกรอบมองแนวราบ
    ของโหมดจอแบน ถ้าผู้เรียนหรือห้องเรียนพบว่าต้องแหงนเกินไป ใช้ `?cluster=1` ได้ทุกเมื่อ

### 1.2 การฉาย = `π(x)` และสิ่งที่หายไป

ให้ `q = x − x̄` และ basis ที่เลือก `{v₁…v_k}` (orthonormal จาก Jacobi)

```
π(x) = x̄ + Σ_{j≤k} (q·vⱼ) vⱼ          residual = x − π(x)
Var(residual) = tr Ĉ − Σ_j vⱼᵀĈvⱼ      ← เอกลักษณ์ที่แผงตัวเลขคำนวณสดสองทางแล้วเทียบกัน
kept% = Σ_j vⱼᵀĈvⱼ / tr Ĉ
```

บนแผง บรรทัดล่างสุดพิมพ์ทั้งสองข้างของเอกลักษณ์พร้อม `Σ‖x−x̄‖²/(n−1)` ให้เห็นด้วยตาว่า
**ความแปรปรวนรวม = tr Ĉ = Σλ** และช่อง `[gap]` คือผลต่างที่เครื่องวัดได้เอง
(ค่าจริงที่บันทึกในการทดสอบ: `4.1650 = 4.1650 = 4.1650`, `|gap| = 2.0e-15`)

## 2. สามโหมดที่เลือกด้วยการก้มมอง (`ℝ³` `ℝ²` `ℝ¹`) + `⟳` ข้อมูลชุดใหม่

| โหมด | สิ่งที่ถูกวาด | kept% (seed 20261104, n=900) | √Var(residual) |
|---|---|---|---|
| `ℝ³` basis `{v₁,v₂,v₃}` | ข้อมูลทั้งกลุ่ม +แกนทั้งสาม | 100.0% | 0 |
| `ℝ²` basis `{v₁,v₂}` | **แผ่นจุดบนระนาบ** + จุดจางของข้อมูลเดิม + เส้น drop + เส้นประของ `v₃` | 98.90% | 0.2138 (หน่วยข้อมูล) |
| `ℝ¹` basis `{v₁}` | **เส้นจุดบาง ๆ ตาม v₁** + เส้น drop ทุกจุด + เส้นประของ `v₂,v₃` | 79.80% | 0.9175 |

ลำดับที่สื่อต้องรักษาไว้ และ `shot.py` ตรวจทุกครั้ง: `kept(ℝ¹) < kept(ℝ²) < kept(ℝ³)` และ
`rmse(ℝ¹) > rmse(ℝ²) > rmse(ℝ³) = 0`

การ์ด `⟳` (แถวบนขวา) เปลี่ยน `seed → seed+1` → ข้อมูลใหม่ทั้งชุด แกนใหม่ทั้งหมด
ค่าจริงที่วัด: `λ₁ 3.3231 → 2.3648` เมื่อ reseed ครั้งเดียว (ยืนยันว่าไม่ได้หมุนข้อมูลเดิม)
ค่าที่ **คงที่** คือของกระบวนการ ไม่ใช่ของชุดข้อมูล: `λ₁/tr ≈ 80%` ทุก seed เพราะ `σ` ของ
กระบวนการถูกออกแบบให้ `(2.0, 0.9, 0.24)` — ทุก seed ที่ทดสอบได้ `λ₁` 80–89% ของ tr

การ์ด `n 900 → 2400` เปลี่ยน `n ∈ {300, 900, 2400}` (key `S`): จุดที่วาดครบตาม n จริง
และ `λ̂ᵢ` เข้าใกล้ `λᵢ` ของกระบวนการตาม `Var(λ̂ᵢ) = 2λᵢ²/(n−1)` → sd สัมพัทธ์ `√(2/(n−1))`
= 8.18% / 4.72% / 2.89% ตามลำดับ; ค่าเบี่ยงเบนจริงที่วัดได้ 20.66% / 6.01% / 4.46%
(= 2.5σ / 1.3σ / 1.5σ — ภายในขอบที่ข้อทดสอบอนุญาต 5σ)
ข้อนี้คือบทเรียนที่สองของสื่อ: **แกนที่เห็นคือของข้อมูลในมือ ไม่ใช่ของโลก**

`math_check.mjs` ตรวจคณิต **อิสระจากสื่อ**: `jacobiEigen(diag(4,1,9)) = {9,4,1}` และ `‖Ĉv−λv‖ < 1e-11`,
เมทริกซ์หมุนจาก quaternion (det = +1, orthonormal 1e-12), ค่า mean/var ของ Gaussian ที่ตรงทฤษฎี,
χ(t) ของเมทริกซ์ที่รู้ λ ล่วงหน้า, `tr Σ` และ `det Σ` แบบปิด, การสร้างซ้ำได้บิตต่อบิตของ `makeCloud(seed,n)`,
และขอบเขตเชิงทฤษฎีของสิ่งที่ estimator ทำได้:

* `Var(λ̂ᵢ) ≤ 2λᵢ²/(n−1)` → `λ̂ᵢ` ต้องอยู่ภายใน `4·√(2/(n−1))` สัมพัทธ์ของ `λᵢ` จริง (n=300/900/2400)
* `Var(tr Ĉ) = 2Σσᵢᵢ²/(n−1)` → `tr Ĉ` ภายใน 4σ ของ `tr Σ`
* ทิศ: `sin θ(v̂ᵢ, vᵢ) ≤ 3·E‖Ĉ−Σ‖_F / gap` (Davis–Kahan) — ค่าจริงที่วัดได้เล็กกว่า bound หลายเท่า
* `maxᵤ uᵀCu = λ₁` ตรวจด้วยการสแกน 8000 ทิศจริงบน `Ĉ` ของข้อมูลจริง

`shot.py` ยืนยันว่า **สื่อเอง** (ตัวที่รันใน browser) คำนวณตรงกับการคำนวณอิสระใน Python —
`λ σ %`, องค์ประกอบ `vᵢ`, `tr/det/χ(t)`, ตัวเลขทั้ง 9 ช่องของ `Ĉ`, `kept/dropped`, `√Var(residual)`,
`max‖x−πx‖`, `Σ‖x−x̄‖²/(n−1) = tr Ĉ = Σλ`, และ `Var(vⱼᵀx) = vⱼᵀĈvⱼ`

หกเรื่องที่การทดสอบจับได้จริงระหว่างสร้างสื่อครั้งนี้ และควรจำ:

1. **เมนูจมลงใต้พื้น** — `body` (กลุ่มที่:UI อยู่) ถูกวางไว้ที่ origin ของ rig = ระดับพื้น
   การ์ดสามแถวอยู่ที่ `y = −1.12 / −1.20 / −1.24 m` (ก้ม 44°–71°) และแผงตัวเลขที่ `y = −0.96 m`
   แก้ด้วย `body.position.set(0, EYE, 0)` เพื่อให้มุมของ `placeFacing()` วัดจากระดับตาจริง
   `sceneAudit()` จับได้เพราะมันอ่าน `getWorldPosition()` ของการ์ดทุกใบ ไม่ใช่ตัวเลขที่ตั้งใจวาง
2. **เขียน π(x) ผิดในโค้ดทดสอบ** — ความคาดหวังของฉันลบองค์ประกอบที่ถูกเก็บ (ได้ residual แทนภาพฉาย)
   จุดที่วาดต่างจากความคาดหวัง 0.42 m → จับได้ด้วยข้อทดสอบเทียบจุดต่อจุด
3. **`1/n` vs `1/(n−1)`** — ค่า `√Var(residual)` ต่างกัน 0.055% (อัตราส่วน = n/(n−1) เป๊ะ)
   เพราะอีกฝั่งหารด้วย n; แก้ให้ตรงนิยามเดียวกับ `Ĉ`
4. **`‖Ĉvᵢ − λᵢvᵢ‖` รายงานผิด** — comprehension ใช้ตัวแปรชื่อเดียวกับ index ของ eigenvalue
   จับคู่ผิดช่อง (ค่าที่ควรเป็น 1e-15 โผล่ออกมาเป็น 2.2)
5. **ความละเอียด float32** — จุดที่วาดถูกเก็บเป็น `Float32BufferAttribute` (~1e-7 สัมพัทธ์)
   ระยะจากแผ่นระนาบที่วัดได้ 8.7e-8 m จึงต้องใช้เกณฑ์ 3e-6 m และเขียนเหตุผลไว้ในโค้ด
6. **`dirW` map `worldOf` สองรอบ** — ผู้ใช้ดูภาพจริงแล้วบอกว่า “จุดที่แบนใน 2 มิติยังไม่แนบกับแผ่นระนาบ”
   โค้ดส่งทิศทางของแกน/ระนาบผ่าน `worldOf` แล้วmultiply ด้วย `(x, z, −y)` อีกที = หมุน 180° รอบแกน x
   ของโลก ทำให้แผ่น `v₁∧v₂` เอียงออกจากข้อมูลจริง (และทำให้ป้าย `σ₁ 2σ₁ …` ชี้ผิดทิศ)
   ลูกศรสองหัวและทรงรีสมมาตรจึงดูไม่ผิด — จับได้เมื่ออ่าน **มุม 4 จุดของแผ่นที่ถูกวาดจริง** กลับมาจาก
   geometry แล้วเทียบกับ `worldOf(vⱼ)` (1−|dot| = 0.64 ก่อนแก้, 1e-9 หลังแก้)
   บทเรียน: ตรวจ “สิ่งที่วาด” ไม่ใช่ “ตัวเลขที่ตั้งใจส่งเข้าไปวาด” และ `Matrix4.elements` เก็บ column-major
   (คอลัมน์ `i` เริ่มที่ index `4i`) — อ่านผิดที่นี้ทำให้ค่าที่ audit รายงานเพี้ยนไปอีกชุดหนึ่ง

## 8. สถานะงานและข้อจำกัดที่พูดตรง ๆ

* ผ่าน `math_check 1401/1401` และ `shot.py 1150/1150` พร้อมภาพนิ่ง 12 ภาพที่ตรวจด้วยสายตาแล้ว
  (ทั้งสามโหมดเมนู แผงตัวเลข การ์ด ภาพ “ℝ² โล่ง ๆ” ที่เห็นการแนบแผ่นชัด และโหมดจอแบน
  อ่านออกทุกข้อความ ไม่มีข้อความล้นออกนอกแผง
  วัดด้วย `measureText` ของหน้าจริง: 0 ข้อความเกินขอบ จาก 117 ข้อความบนแผงและ 207 บนการ์ด)
* **ยังไม่ได้ทดสอบใน headset จริง** — ทุกภาพนิ่งใน `_preview/` มาจาก Chromium โหมดจอแบน
  (ตรรกะการคำนวณและการจัดวางเดียวกัน แต่กรอบมอง 64° ไม่ใช่ FOV ของแว่น)
  ยังไม่มีข้อมูลว่า ผู้เรียนก้มเจอ `ℝ²` `ℝ¹` เจอเร็วแค่ไหน, 1.2 s dwell นานไปหรือสั้นไป,
  หรือกระจุก default (ขยาย 2 เท่า) ที่ระยะ 1.5–4.0 m ซึ่งสูงถึง 3.2 m ทำให้ต้องแหงนหรือเวียนศีรษะหรือไม่
* **การขยายกระจุก ×2 ทำให้ยอดของกระจุกสูงเกินกรอบแนวตั้งของจอแบน ในกรณีข้อมูลตั้งสูง** —
  วัดจากหน้าจริง 1440×900 (ครึ่งกรอบมอง 45.0° แนวยาว / 32.0° แนวดิ่ง) ที่ท่ามองตรง `look=0`:
  `seed 20261104` elev ถึง +20.2° az 29.6° (k=1: +6.8° / 15.9°) · `seed 7` (กว้าง–แบน) az 40.7° (k=1: 27.1°)
  · `seed 1` (ตั้งสูง) **elev +35.2° ซึ่งเลยกรอบ 32.0°** (k=1: +14.6° อยู่ในกรอบ)
  บนจอแบนจึงเห็นยอดของกระจุกถูกตัดได้ถ้ามองตรง — แก้ได้ด้วย `?look=0.35,0` (เงยกล้อง) หรือ `?cluster=1`
  ในแว่นจริงกรอบแนวตั้งกว้างกว่านี้มาก แต่เรขาคณิตเดียวกันนี้แปลว่า *ต้องเงยคอ* ถึง ~35° เพื่อเห็นยอด
  ตัวเลขทั้งหมดเป็นของโหมดจอแบน (scene audit ของสื่อเอง) ยังไม่ใช่สิ่งที่ผู้เรียนจริงรายงาน
* **การ์ดรอบนอกไม่อยู่ในจอแบน**: แถว 1 มีการ์ดที่ az ±49° และแถว 2 ที่ ±58° ซึ่งนอกกรอบจอ 1440×900
  (ครึ่งกรอบ ~46.5°) แต่อยู่ใน FOV ของแว่น — บนจอแบนใช้ `1 2 3 4 5 6 7 8 9` หรือแถบ `%` บนแผง
  เลือกการเดียวกันได้ และ HUD พิมพ์ค่าเดียวกันออกมาเป็นตัวเลข
* **ป้ายชื่อของแกนที่สั้นมากยังเบียดกันตรงกลาง** — λ₃ ≈ λ₁/70 ทำให้ `v₃` สั้นเพียง ~0.03 m
  ได้แก้สองชั้นแล้ว (ซ่อนป้าย σ ที่ใกล้ `x̄` เกิน 0.07 m; เลื่อนป้ายชื่อแกนไปรัศมีขั้นต่ำ 0.30 m)
  แต่ภาพยังแสดง `σ₁ 2σ₁ σ₂ 2σ₂ x̄` ซ้อนกันเป็นแถบบริเวณกลางกระจุก
  ทางที่ควรทำถ้าจะให้ดีขึ้น: ตัดขีด/ป้าย σ ของแกนที่ไม่ได้เป็นแกนหลักของโหมดที่ดูอยู่
* **ขนาดจุด ×2 ทำให้กระจุกทึบขึ้น** — default วาดจุดเส้นผ่านศูนย์กลาง 0.040 m (เดิม 0.020 m)
  ที่ระยะ 1 m ซึ่งเมื่อ `sizeAttenuation:true` คือขนาดเชิงโลกคงที่ไม่ว่าอยู่ไกลเท่าไร
  ใน `ℝ²` ที่ n = 900 จุดจะชิดกันจนเป็นแผ่นทึบใกล้กลางกระจุก (เห็น “การยุบเป็นแผ่น” ชัดแต่เห็น
  การเรียงตัวละเอียดน้อยลง) — ถ้าต้องการเห็นจุดเป็นจุดให้ `?dots=1` หรือ `?dots=1.5`;
  ฝั่งกลับกัน `?dots=3` ใช้แสดงโครงสร้างหยาบให้ห้องระยะไกล อ่านค่าที่วาดจริงได้จาก
  `__pca.stats().scene.pointDraw`
  การขยายกระจุกไม่ทำให้จุดบนจอโตขึ้นซ้ำอีกชั้น: สื่อชดเชยขนาดจุดด้วยระยะเวทีแล้ว
  (`?cluster=2` ให้กล่องใหญ่ขึ้น แต่จุดบนจอคงขนาดเท่าเดิม — ยืนยันด้วยการอ่าน `material.size`)
* **ข้อมูลเป็นข้อมูลจำลองโดยออกแบบ** — กระจุกคือ Gaussian ellipsoid จาก `makeCloud` ไม่ใช่ข้อมูลจริงของนักศึกษา
  สอน "หน้าตาของการฉาย" และ "ทำไม v₁ ชนะ" ได้ แต่ไม่ได้อ้างว่าข้อมูลจริงจะเป็นทรงรี
* ตัวอักษรบนแผงใน headset จริงยังไมได้ทดสอบ: แผง 0.984×0.437 m ที่ 2.05 m → จุดภาพ 0.68 mm,
  ตัวอักษร 20–24 px สูง ≈ 13–16 mm = ~0.4° ของมุมมอง; บนจอแบนมี HUD ที่พิมพ์ชุดตัวเลขเดียวกัน
  ด้วยอักษรใหญ่กว่า ถ้าในแว่นอ่านไม่ออกต้องลดจำนวนตัวเลขบนแผงแล้วขยายตัวอักษร (ยังไม่ได้ทำ)
* **ยังไม่มีความยาวจริงของ variance ในร่างกายผู้เรียน** — ดู §1.1; และ `x̄` ของข้อมูลไม่ได้ตรงกับ
  จุดที่ผู้เรียนยืน (สื่อแสดง `μ ‖μ‖=0.50` ให้เห็นชัดเจนว่าคนละจุด)
* ใบงานคู่สื่อยังไม่เขียน — สิ่งที่ภาพตอบไม่ได้และใบงานต้องถาม:
